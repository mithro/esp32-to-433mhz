# ESP32-C3 SuperMini + CC1101 — Tasmota 433 MHz node

**Status (2026-09-05):** design + host-tested decoders + bench tooling; the
Tasmota firmware is the overlay in `firmware/` (Plan B). On-hardware validation of
the radio foundation (detect / register-I/O / selection) and the CC1101 OOK
edge-capture path is recorded in [`HWTEST-RESULTS-cc1101.md`](HWTEST-RESULTS-cc1101.md);
bench captures of the remotes/Merlin are still pending a human at the bench.

A small WiFi/USB 433 MHz transceiver: an **ESP32-C3 SuperMini** driving a
**D-SUN CC1101** SPI module (or an Ebyte E07-M1101D, or an SX1278 RA-02), running
Tasmota with a custom CC1101/SX1278 driver. Receives the Fineoffset weather
stations (FSK), the OOK-PWM remotes and the Merlin garage remote, transmits OOK
(`CcRfSend`) and Security+ 2.0, and publishes rtl_433-shaped JSON + `RfReceived`
to MQTT (and the same over its native-USB console).

> **Scope note.** The consolidated firmware in `firmware/` builds the radio
> *foundation* (detect / register-I/O / radio selection) plus the existing CC1101
> OOK + decoder functionality. The SX1278 FSK/OOK/LoRa RX/TX functional features
> are **not built yet** (later work) — see `firmware/src/cc1101_node/sx1278_radio.cpp`
> for the staged roadmap.

The board carrier/adapter (KiCad) and the full design spec live elsewhere: the
KiCad adapter is this repo's top-level [`README.md`](../../README.md) and
`hardware/`; the design spec and the numbered rulings (R1-R8) are in the project
repo (github.com/mithro/433mhz, `docs/.../2026-08-20-esp32c3-cc1101-tasmota-design.md`).

## Wiring

The wiring diagram is generated by [`../tools/esp32c3-cc1101-node-wiring.py`](../tools/esp32c3-cc1101-node-wiring.py)
(its `WIRES` table is the single source of truth, checked by `tests/test_common.py`).

| D-SUN pin | ESP32-C3 GPIO | Role | Why |
|---|---|---|---|
| VCC | 3V3 | 3.3 V supply (~35 mA peak in TX) — **never 5 V** | SuperMini LDO is adequate |
| GND | GND | | |
| SCK | GPIO4 | SPI clock | Arduino-core FSPI default |
| MOSI (SI) | GPIO6 | SPI -> CC1101 | FSPI default |
| MISO (SO) | GPIO5 | SPI <- CC1101 (also CHIP_RDYn while CS low) | FSPI default |
| CSN | GPIO7 | chip select | FSPI default |
| GDO0 | GPIO3 | FSK: packet-ready IRQ; OOK: **TX data in** (RMT out) | no boot role |
| GDO2 | GPIO10 | OOK: **RX demod data out** (RMT capture in); FSK: spare status | no boot role |

**Do not use** GPIO2/8/9 (strapping; 8 is the blue LED, 9 is BOOT), GPIO20/21
(UART0, kept free as a fallback console), GPIO18/19 (USB D-/D+). After reset
GDO0 outputs CLK_XOSC/192 until configured — harmless on GPIO3. The D-SUN
header is 2x4; pin names as on its silkscreen: (VCC GND) (SCK MOSI) (GDO2 MISO)
(CSN GDO0). The SuperMini's PCB WiFi antenna is marginal: placement matters.

Per-board pin maps (blue E07, green D-SUN, SX1278 RA-02) that the firmware
probes at boot are tabulated in [`../README.md`](../README.md) -> *Radio
selection and SX1278 (RA-02) support*.

### Tasmota template
`GPIO4=SPI CLK, GPIO5=SPI MISO, GPIO6=SPI MOSI, GPIO7=CC1101 CS, GPIO3=CC1101 GDO0, GPIO10=CC1101 GDO2`, then `Module 0`.
See [`../README.md`](../README.md) -> *Commissioning a node* for the exact raw
`Template` array (the GDO pin functions are gated behind `USE_KEELOQ` upstream,
so only the raw array assigns them in this build).

### Reference setup on rpi5-433mhz (direct SPI, no ESP)

| D-SUN | Pi 5 header | BCM |
|---|---|---|
| VCC | pin 1 | 3V3 |
| GND | pin 6 | GND |
| SCK | pin 23 | GPIO11 SCLK |
| MOSI | pin 19 | GPIO10 MOSI |
| MISO | pin 21 | GPIO9 MISO |
| CSN | pin 24 | GPIO8 CE0 (`/dev/spidev0.0`) |
| GDO2 | pin 18 | GPIO24 — **black** wire (OOK capture, [`../tools/cc1101_ook_capture.py`](../tools/cc1101_ook_capture.py) `--gpio 24`) |
| GDO0 | pin 22 | GPIO25 — **green** wire (reserved for async TX tests) |

GDO assignment measured 2026-08-22 with [`../tools/cc1101_find_gdo_pins.py`](../tools/cc1101_find_gdo_pins.py)
(drives each GDO to a fixed level and scans the header: `GDO2 -> GPIO24 (header
pin 18)`, `GDO0 -> GPIO25 (header pin 22)`); wire colours as recorded by Tim.
The 3V3/GND pin numbers are the conventional choice, not measured. The Pi-side
reference driver is [`../tools/cc1101.py`](../tools/cc1101.py), which the firmware
presets are proven against (`tests/test_presets.py`).

## Why these choices (so they aren't relitigated)
- **Why RMT:** the C3's RMT peripheral timestamps edges in hardware (1 us) and
  buffers them; WiFi/MQTT cannot jitter pulse measurement; the same peripheral
  generates exact TX pulse trains, which Security+ 2.0 needs.
- **Why two GDOs:** packet mode (FSK) wants an IRQ on GDO0; async-serial mode
  (OOK) wants RX data on GDO2 and TX data on GDO0. The D-SUN has both.
- **Why not ESPHome/Berry:** estate and HA are Tasmota; stock Tasmota has no
  CC1101 driver and Berry has no SPI/RMT — see the design spec section 2.
- **FSK vs OOK exclusivity:** a CC1101 does one at a time; nodes get a role
  (`CcMode weather|remotes`).
